База: v1.1.0 build 5 (NSOutlineView вместо SwiftUI Table, NSScrollView, сортировочные ключи schema v2).
Правило работы: **один пункт за итерацию** — правка → сборка → тесты → установка → пуш → отчёт →
ждём команду владельца. Не трогать следующий пункт без явного «можно».

## Пункты (приоритет сверху вниз)

### P0 — №1 Сортировка не работает вообще
Симптом: индикатор в заголовке меняется, данные не перестраиваются (как в первом релизе).
Анализ: подозрение на двойной механизм — AppKit сам циклит sortDescriptorPrototype и вызывает
`sortDescriptorsDidChange`, плюс наш `sync()` перезаписывает `table.sortDescriptors` на КАЖДОМ
updateNSView (возможен повторный вызов делегата → гонка/сброс).
Решение: один явный механизм — `tableView(_:didClickTableColumn:)` → чистая функция
`RowSorting.nextSort(current:column:)` (первый клик = forward, повторный = flip, чужой столбец = forward).
Убрать sortDescriptorPrototype (иначе два механизма конфликтуют). Индикатор — программная установка
`table.sortDescriptors` только при реальном изменении, под suppress-флагом. В `sortOrder` didSet —
guard от одинаковых значений.
- [x] nextSort + unit-тесты (цикл flip, смена столбца, пустой список)
- [x] didClickTableColumn вместо sortDescriptorsDidChange
- [x] suppress-флаг на программную установку sortDescriptors
- [x] guard в sortOrder didSet
- [x] сборка + 31 тест + установка (v1.1.0 build 6, 2026-11-04)
- [x] финальный фикс: SortHeader с ненулевым фреймом; сортировка подтверждена владельцем (build 9)

### P1 — №3 Иконки пропадают/сжимаются при узком столбце
Причина: NSStackView сжимает NSImageView при нехватке места (нет фиксированных размеров).
Решение: фиксированные констрейнты иконки (width=height=14, priority .required), тексту — низкий
compression resistance (truncates вместо выталкивания иконки), hugging иконки высокий.
- [x] констрейнты в CellFactory (name 15px + flags 13px, required; тексту — defaultLow compression)
- [x] проверка: иконки у всех строк на живом скриншоте (build 10)
- [ ] проверка владельцем: узкая колонка + скролл + растяжение-возврат

### P2 — №4 Автоподбор ширины по двойному клику на границу
Делегат `tableView(_:sizeToFitWidthOfColumn:)` вызывается AppKit при двойном клике на правую границу
столбца — это ровно «столбец слева от границы» (семантика Excel). Измерение максимальной ширины
значений колонки: фоновый проход по строкам (1M+ — измерять NSFont-метрикой, не вьюхами), затем
установка ширины + persist.
- [x] ColumnFit.swift (замер по NodeFormatters/шрифтам ячеек, cap 900, min 40) + 4 юнит-теста
- [x] делегат: запрос синхронный → замер фоновой → применение + persist (без фриза на больших картах)
- [x] сборка + 35 тестов + установка (build 11)
- [ ] проверка владельцем (двойной клик на границу «Имя»)

### P2.6 — Баг: дублирование столбцов при смене видимости
Иногда после переключения отображаемых столбцов появляются дубли (дважды «Имя»). Подозрение:
реентерабельность — columnDidResize/Move уведомления срабатывают ВНУТРИ rebuildColumns →
persistColumnLayout пишет session.columnLayout → повторный rebuild. Решение: флаг isRebuilding
(гасить persist во время пересборки) + uniqued у visible + один persist после пересборки.
- [x] флаг + uniqued + persist (первый заход был insufficient — см. ниже)
- [x] НАСТОЯЩАЯ причина: NSOutlineView нельзя удалить outline-колонку через removeTableColumn:
      (AppKit: "cannot remove outlineTableColumn") — старая rebuild оставляла её и добавляла дубль.
      TableColumnRebuilder: перекинуть outline на выживающую колонку → удалить лишние → добавить
      недостающие → moveColumn доворот порядка. Регресс-тесты TableColumnRebuilderTests (5).
- [ ] проверка владельцем (потыкать меню столбцов быстро; переставить Имя/Тип; потогать)

## Известные ограничения
- Сортировочные ключи: числа >8 значащих цифр в имени сортируются неточно (документировано).
- Байт-порядок ключей: не-ASCII после ASCII, диакритика стрипается (осознанный компромисс).
- Дерево: полный проход при rebuild O(n) на фоне — ок.
